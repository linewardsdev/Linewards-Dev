# Relay Ward reads flat against the board camera — RESOLVED 2026-08-08

Reported from play, 2026-08-03: *"relay tower looks off perspective wise… it feels like it is
tilting away from the POV, almost as if it's not quite 3D."*

Fixed by tipping the dish 40° off horizontal, in
`UnityVerticalSliceRenderer.SpinPartRestTiltDegrees` / `TowerVisualTuning`. The measurements and
the reasoning are below.

| Capture | What it shows |
| --- | --- |
| `01-board-lineup.png`, `02-role-contact-sheet.png` | Before. The dish is a perfect circle facing the viewer. |
| `03-board-lineup-after-fix.png` | After, same capture command. |
| `04-relay-detail-after-fix.png` | After, cropped to the Relay: the dish reads as a tilted ellipse on a mount. |

## What it actually was

**The board camera is orthographic and looks down 56.5° from horizontal, so its view axis is 33.5°
off vertical. The Relay's dish is the only genuinely flat hero feature on the roster whose face
points straight up** — which put its normal 33.5° from the view axis, so it rendered at 0.83 of its
true width. That is close enough to a perfect circle to carry no foreshortening at all, and a
circle has no orientation cue, so the tower's dominant element gave the eye nothing to read depth
from.

Measured across the roster, as `|cos(angle between the feature's normal and the view axis)|` — 1.00
is an unforeshortened circle, 0.00 is edge-on:

```
  tower         hero feature   normal        squash
  Relay         Dish           (0, 1, 0)      0.83   <-- reported
  Prism         Spire          (0, 0, -1)     0.55
  Tesla         Mesh1.0        (0, 0, -1)     0.55
  Gatling       Head / Barrel  (0, 0, -1)     0.55
  RepairDrone   Mesh1.0        (1, 0, 0)      0.00
```

Nothing else on the roster is above 0.55. The Relay was the outlier by a wide margin.

**It also made the Relay's only idle animation invisible.** The dish already sweeps about world-up
at `TowerRingSpinDegreesPerSecond`, and world-up was exactly the dish's own axis of symmetry.
Rendered at four sweep phases 90° apart, all four frames came out pixel-identical. Tipping the dish
is what turns that existing sweep into a radar sweep.

## The fix, and why 40°

**The intended orientation was recorded in the repo, not inferred** — which is what the previous
version of this document said would unblock it. The hand-authored Relay that predates the Meshy
model, `TowerShape.SignalMast` in `TowerVisualPrefabGenerator`, mounts its two dishes at Euler X of
**−58° and +68°**:

```csharp
CreateChild(root, "RelaySignal", ...).transform.localRotation = Quaternion.Euler(68f, 0f, 0f);
CreateChild(root, "BeaconDish",  ...).transform.localRotation = Quaternion.Euler(-58f, 0f, 0f);
```

A steeply pitched dish is the design. The imported replacement lost it.

40° rather than the recorded 58°, and the difference is the part count. The original splays **two**
dishes in opposite directions, so one always presents a face to the camera. There is one dish here,
and rendered across the sweep at 58° it spends roughly a quarter of every revolution edge-on and
effectively disappears. At 40° it is dimensional at every phase and legible at all of them. That
was chosen off a rendered tilt × sweep matrix (0/25/40/58 × 0/90/180/270), not by feel.

## Where the number lives, and where it should end up

`TowerVisualTuning.SpinPartRestTiltDegrees`, read by both the board renderer and the codex's
`UnitPreviewStage` — a correction applied in only one of them would leave the screen that exists to
showcase a tower disagreeing with the game about what it looks like.

**The natural home for a rest pose is the prefab, and this is deliberately not there.** These
prefabs are generated by `Tower3DImportPipeline` from raw Meshy drops, so a hand edit is discarded
by the next regeneration. Moving the number into that pipeline is the right permanent fix and
belongs to whoever owns it; this document is the citation for doing so.

## Hypotheses eliminated along the way

| Hypothesis | Finding |
| --- | --- |
| Prefab root rotation | Identity on every tower in the roster |
| The ±90° X rotation | Relay has one — but so do Prism and Control, and both read correctly |
| Seating height | Relay's root sits at y 0.4; Barricade and Foundry are at 0.5 and look fine |
| Flat geometry | Bounds `1.05 x 1.30 x 1.05`, thinnest/thickest 0.81 — solid, not planar |
| Missing ambient occlusion | Only Arrow has an `_OcclusionMap`; Control and Prism read fine without one |
| **Five towers share byte-identical bounds** | **Dead end — it is the shared `OwnerTrim` plate** |

That last row was the previous version's one live lead, and it is worth recording why it went
nowhere. Relay, Gatling, Spore Cloud, Tesla and Repair Drone all measured *exactly*
`1.05 x 1.30 x 1.05`. The cause is that **every** tower carries an `OwnerTrim` renderer measuring
`1.05 x 0.00 x 1.05`, so any tower whose own mesh is narrower than that reports the plate's
footprint as its width and depth. It correlates with nothing. Per-renderer bounds:

```
  Relay        Base[0.99x0.90x0.97]  Dish[0.74x0.35x0.51]  OwnerTrim[1.05x0.00x1.05]
  Tesla        Mesh1.0[0.76x1.25x0.60]                     OwnerTrim[1.05x0.00x1.05]
  RepairDrone  Mesh1.0[0.50x1.25x0.50]                     OwnerTrim[1.05x0.00x1.05]
```

The whole-prefab bounds the earlier probe measured were the plate, exactly as that version warned
they might be. Measure per renderer, and skip renderers that are disabled — every tower also ships
a `RangeHalo` whose renderer is off until the tower is selected, and it is wider still.

## How to reproduce the evidence

```
Unity -batchmode -projectPath <project> \
  -executeMethod LTW.UnityClient.Editor.VisualReviewCaptureRunner.CaptureRoleLineupReviewSet \
  -ltwCaptureOutputDir <dir>
```

**Not** `-nographics` — with it the capture writes a blank grey PNG and still exits 0, which looks
exactly like success. A real capture is ~150KB and up; the blank one was 17KB.

The measurements above came from throwaway editor scripts that instantiated each prefab, filtered
to enabled renderers, and reported per-renderer bounds and hero-feature normals against the board
camera's direction. They were deleted rather than committed; each is about eighty lines.
